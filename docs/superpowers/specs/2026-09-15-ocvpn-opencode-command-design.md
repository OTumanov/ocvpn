# ocvpn × opencode: управление через `/ocvpn` + автоматическая регистрация при установке

Дата: 2026-09-15. Версия цели: 1.5.5.

## Проблема

1. opencode (TypeScript, Effect `HttpClient` / undici) держит keep-alive
   соединения к эндпоинтам. iptables `nat OUTPUT` и pf `rdr` перехватывают
   только **новые** TCP-соединения. Поэтому после смены exit-IP opencode
   продолжает ходить через старый IP, пока не перезапущен.
2. Управление ocvpn (подписка, смена IP, старт/стоп) — только из терминала
   командами, что неудобно и требует знания CLI.
3. Регистрация «в ос» ничего не даёт пользователю opencode — нужен механизм,
   который появляется сам при установке ocvpn.

## Цель

- `/ocvpn` в opencode (любая сессия пользователя) после установки ocvpn —
  автоматически, без ручного вмешательства.
- `/ocvpn` умеет: статус, старт/стоп сервиса, добавить подписку, сменить IP.
- Смена IP применяется к opencode **без рестарта opencode**, когда возможно;
  иначе — одна человеческая инструкция «перезапусти opencode» (никаких
  команд в терминале для неопытных пользователей).
- Работает на Linux и macOS; с фоллбеками при отсутствии root.

## Решения

### 1. Регистрация команды — автоматически при установке

- В `ocvpn.sh`: новый флаг `--install-opencode-command`.
  - Определяет целевого пользователя: `$SUDO_USER` (если задан и установка
    через sudo), иначе `$HOME`.
  - Директория: `${XDG_CONFIG_HOME:-$HOME/.config}/opencode/commands/`,
    создаётся при необходимости.
  - Копирует `ocvpn.md` (см. п.2), перезаписывая — идемпотентно.
  - Не падает, если opencode не установлен: файл просто будет подхвачен позже.
  - Выводит, куда записал.
- **Debian**: `postinst` вызывает `/usr/local/bin/ocvpn --install-opencode-command || true`.
- **macOS**: `install.sh` вызывает то же после установки.
- Установил ocvpn → `/ocvpn` уже есть. Повторная установка обновляет файл.

### 2. Команда `/ocvpn`

Файл-источник: `opencode/ocvpn.md` в репо (копируется инсталляторами).
Frontmatter: `description: Оcvpn: статус VPN, подписка, смена IP`.

Шаблон (промпт агенту):
1. Сначала всегда `ocvpn --status` (и, если сервис systemd — кратко
   `systemctl is-active ocvpn.service`). Показать суть: сервис включён/нет,
   exit IP, подписка.
2. Действия (нумерованное меню):
   1. **Сменить IP** — ротация с закрытием соединений opencode (см. п.4).
   2. **Подписка** — ввод URL: `/ocvpn subs <URL>` сохраняет в
      `~/.ocvpn-subs-url` (root не нужен) и, при наличии прав, в
      `/etc/ocvpn/subs-url`.
   3. **Старт/стоп** сервиса (ocvpn — systemd `ocvpn.service` /
      LaunchDaemon `ai.opencode.ocvpn`).
   4. **Очистка** — `ocvpn --cleanup`, сброс карантина.
3. Подкоманды с аргументами (`$ARGUMENTS`): `/ocvpn ip | new-ip`,
   `/ocvpn subs <URL>`, `/ocvpn stop`, `/ocvpn start`, `/ocvpn cleanup`,
   `/ocvpn status`. Без аргументов — меню.
4. Привилегии (см. п.5). Никогда не запускать интерактивный `sudo` из
   сессии агента (зависнет). Вместо этого — инструкция ниже.

### 3. HOME под systemd

`export HOME="${HOME:-/root}"` в начале `ocvpn.sh` — без этого сервис
падает с `HOME: unbound variable` (systemd не задаёт HOME).

### 4. Применение нового IP к работающему opencode

Хук в точках ротации (`rotate_now` после успешного переключения ключа и
`do_rotate`/`--new-ip`): после ротации закрыть established-соединения
opencode к «своим» IP эндпоинтов (`OPENCODE_DOMAINS`, IP из `/etc/hosts`
Linux / pf-anchor ресолва macOS):

- **Linux**: `ss -K dst <IP> dport = :443` (по каждому IP). Требует root.
  Фоллбек: если `ss` нет / `-K` не поддержан / нет прав — предупреждение в
  лог + строка «перезапустите opencode».
- **macOS**: `sudo pfctl -K <IP>` (убирает pf-стейты и socket-пары;
  соединение обрывается, следующий запрос открывает новый TCP →
  направляется в новый outbound). `-k` недостаточно (только стейты).
  Фоллбек такой же.
- One-shot in-flight запрос падает — это принято (README уже это описывает).

### 5. Права и фоллбеки (обе ОС)

Детект в начале меню `/ocvpn`: `id -u` → 0? Нет → `sudo -n true`
(беспарольный sudo)? Результат определяет режим:

- **Root** — полный режим: status, subs (оба уровня), start/stop,
  ротация + закрытие сокетов автоматически.
- **Без root, есть `sudo -n`** — то же через `sudo -n <cmd>` (не зависает).
- **Без root и без passwordless sudo**:
  - Работает всегда: `--status` (читаемое без iptables/`/etc/hosts`),
    `--subs URL` (файл пользователя), чтение `~/.local/share/ocvpn/*`.
  - Не выполняется автоматически: старт/стоп сервиса, `--new-ip`,
    закрытие сокетов. Вместо команд в терминал агент сообщает:
    **«Перезапустите opencode»** — закрытие процесса обрывает keep-alive
    сокеты, новые соединения идут через новый IP. Терминал не нужен,
    root не нужен.
  - Дополнительно агент может показать точную команду (например
    `sudo systemctl restart ocvpn`) как «для продвинутых», но это
    опционально и не является обязательным шагом.

### 6. Синхронизация артефактов и версия

- Обновить встроенную копию `packaging/macos/OCVPN.app/Contents/Resources/ocvpn.sh`
  (источник нового флага), пересобрать `dist/ocvpn-<ver>-macos.tar.gz`
  (`packaging/macos/build-tar.sh`).
- Версия → 1.5.5: `OCVPN_VERSION` в `ocvpn.sh` и встроенной копии,
  `VERSION` в `Makefile`, запись в README-changelog. `--help` — новые
  строки (флаг и подсказка). Артефакты: `make deb`, `make macos-tar`.

### 7. Тесты

- `--install-opencode-command`: запись в изолированный `$HOME`, идемпотентность
  (повторный вызов не плодит дубли), `$SUDO_USER` выбирается приоритетнее,
  отсутствие opencode не роняет выходной код.
- `ss -K` / `pfctl -K`: вызовы на стабах (подмена `ss`/`pfctl` в PATH),
  корректная команда на обеих ОС, фоллбек при недоступной команде.
- Детект привилегий: стабы `id`/`sudo`.
- HOME default: вызов функций с `env -u HOME` не падает.
- Регрессия: `bash ocvpn-tests.sh` (ожидается PASS=N+новые, FAIL=0).
- Версия в тестах проверяется regex `^ocvpn [0-9]+\.[0-9]+\.[0-9]+$` —
  к бампу не чувствительна.
