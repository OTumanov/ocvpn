# ocvpn

Минимальный bash-скрипт для прозрачной маршрутизации только эндпоинтов [opencode](https://opencode.ai) через VLESS-VPN. Весь остальной трафик хоста не затрагивается.

## Как работает

1. Скачивает актуальный список VLESS-ключей из подписки
2. Берёт 10 случайных серверов, параллельно пингует их (TCP-connect)
3. 5 лучших по пингу — кандидаты; пробует подключиться через xray
4. Первый рабочий ключ → настраивает прозрачный прокси (iptables REDIRECT)
5. **Только** трафик к IP-адресам `*.opencode.ai`, `zenmux.ai`, `ai.zenifra.com`, `auth.openai.com` на порту 443 идёт через VPN
6. Всё остальное на хосте — напрямую (nginx, SSH, приватные сети, остальной интернет)

Каждый запуск = новый случайный ключ из подписки.

## Быстрый старт

```bash
# Клонировать и запустить
git clone git@github.com:OTumanov/ocvpn.git
cd ocvpn
bash ocvpn.sh
```

Скрипт автоматически:
- Установит xray (если не найден) в `~/.local/opt/xray`
- Скачает список ключей
- Найдёт рабочий сервер
- Поднимет прозрачный прокси

После successful запуска — запускай opencode как обычно.

## Команды

| Команда | Описание |
|---------|----------|
| `bash ocvpn.sh` | Запустить VPN, найти рабочий ключ, настроить маршрутизацию |
| `bash ocvpn.sh --cleanup` | Снять iptables-правила, убрать форсировку IPv4 из /etc/hosts |

## После запуска

Скрипт выводит статус и остаётся висеть в foreground. Чтобы запустить opencode — открой новую сессию/вкладку и запусти `opencode` как обычно. Маршрутизация работает на уровне ядра (iptables nat), поэтому opencode автоматически ходит через VPN без переменных окружения.

Для смены ключа — `Ctrl+C` и запусти `bash ocvpn.sh` заново (новая случайная выборка).

## Тесты

```bash
bash ocvpn-tests.sh
```

Покрывает:
- Парсинг всех типов VLESS-конфигов (reality, ws, tls, grpc, xhttp)
- Декодирование URL-encoded параметров (path, sni)
- Логику отбора кандидатов (TCP-пинг, сортировка, отбрасывание мёртвых)
- Индемпотентность /etc/hosts (не плодит дубликаты при повторных запусках)
- Парсинг 5 реальных ключей из живой подписки

## Зависимости

- `curl`, `python3`, `unzip`, `iptables`
- Рут (для iptables и установки xray)
- Linux ( протестировано на Ubuntu)

## Что не трогает

- Nginx / проксируемые сайты (80, 443 входящие)
- SSH (22)
- Приватные подсети (10.0.0.0/8, 192.168.0.0/16, 172.16.0.0/12)
- Docker-сети
- Существующие TCP-соединения (iptables nat OUTPUT работает только на новые)

## Портрум

| Порт | Назначение |
|------|------------|
| `10808` | SOCKS5 прокси (localhost) |
| `10809` | HTTP прокси (localhost) |
| `12345` | Прозрачный прокси (iptables REDIRECT) |

Все порты слушают только на `127.0.0.1`, наружу не публикуются.

## Конфигурация

Параметры в начале скрипта:

```bash
BATCH_SIZE=10    # сколько случайных ключей пинговать
MAX_TRIES=5      # сколько лучших кандидатов пробовать
PING_TIMEOUT=3   # таймаут TCP-пинга (сек)
TIMEOUT=5        # таймаут теста generate_204 (сек)
```
